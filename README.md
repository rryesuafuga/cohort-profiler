# cohort-profiler

Upload a REDCap export, get a descriptive and univariate analysis report back
as Word and PDF.

The app validates the export against a declarative spec before it analyses
anything. Study knowledge — variable names, source columns, labels, valid
ranges, factor levels, consistency rules — lives in `spec/*.yaml`, never in the
R code, so pointing this at a second study means writing a second spec rather
than forking the app.

The first spec is `spec/vital-hmb.yaml`: the VITAL-HMB study, outcome = heavy
menstrual bleeding by alkaline hematin.

## Why the validation gate exists

The report this replaces matched columns by substring of the REDCap *label*.
When a column was missing or renamed, the match silently returned all-NA and a
full analysis ran on nothing. `validate_export()` turns every variant of that
into a loud failure, and reports every problem at once rather than stopping at
the first — study teams re-export once and need the whole list.

**Hard failures** stop the render: a missing or empty outcome column, a missing
record ID or event column, duplicate record IDs, a missing `required` variable,
a `source` string matching more than one column, a changed questionnaire item
count, or an empty analytic sample.

**Soft failures** are reported in the document's data-quality section: unmatched
optional columns, values outside a declared range, responses the spec does not
declare, variables above the missingness threshold, and consistency-rule
violations.

Error messages are written for the person doing the export:

```
Column "HMB calc" not found in the upload. This looks like a raw-value export
-- re-export from REDCap with labels.
```

## Running it

```bash
Rscript -e 'shiny::runApp(port = 7860, host = "0.0.0.0")'
```

Or in Docker, which is also how Spaces runs it:

```bash
docker build -t cohort-profiler .
docker run -p 7860:7860 cohort-profiler
```

## Development

```bash
Rscript data-raw/make_synthetic_fixture.R                 # regenerate the fixture
Rscript -e 'devtools::load_all(); testthat::test_dir("tests/testthat")'
```

Dependencies are pinned with renv. After adding a package, run
`renv::snapshot()` and commit `renv.lock`.

### Data

`data-raw/synthetic_vital_hmb.csv` is the only dataset in this repo and it is
fully synthetic — 400 participants plus follow-up rows, generated by
`data-raw/make_synthetic_fixture.R` with a fixed seed. It deliberately contains
defects so the validation rules have something to catch: non-answer strings,
out-of-range BMI and heart rate, consistency violations, a duplicated record
ID, an all-missing column, and two predictors that separate the outcome
perfectly.

Real participant data must never enter this repo. `.gitignore` blocks `*.csv`
outside `data-raw/`, and rendered `.docx`/`.pdf` files, since a rendered report
contains data.

## How it fits together

```
app.R                 Shiny UI and server; thin, logic lives in R/
R/spec.R              read_spec(), column matching
R/validate.R          validate_export(): the schema gate
R/build_data.R        build_analysis_data(): export + spec -> tidy frame
R/derive.R            derived variables (asset PCA, MAP, item means)
R/tables.R            descriptive and univariate tables (flextable)
R/render.R            render_report(): Rmd -> DOCX -> PDF
inst/report.Rmd       parameterised report
spec/vital-hmb.yaml   variable spec and consistency rules
data-raw/             fixture generator and the synthetic CSV
tests/testthat/       unit tests plus a full render smoke test
```

Upload → `validate_export()` → `build_analysis_data()` → `render_report()`.
The tidy frame is the only thing the report sees; nothing downstream of
`build_analysis_data()` knows that REDCap exists.

### Output

The report renders once to DOCX with pandoc, and the PDF is that DOCX converted
by headless LibreOffice:

```
soffice --headless --convert-to pdf --outdir <dir> <docx>
```

One rendering path, so the two files cannot disagree. There is no LaTeX in this
pipeline, which is also why every table goes through `flextable` rather than
`gt`.

## Statistical conventions

Carried over from the original report; they were deliberate choices.

- Continuous: median [IQR] and mean (SD), Wilcoxon rank-sum.
- Categorical: n (%) to one decimal, chi-square, falling back to a simulated
  Fisher's exact test when any expected cell is below five.
- Univariate logistic regression per variable, odds ratio with a Wald 95% CI.
- A variable is reported as **not estimable** rather than given a number when
  it has fewer than 30 complete cases, has no variation, or separates the
  outcome perfectly. In VITAL-HMB `treated_anaemia` and `family_bleeding` do
  separate it; fitting them anyway produces an odds ratio around 10^8, which
  reads as a finding rather than as an artefact.
- Missingness: a per-variable table, Little's MCAR test over numeric variables
  below the threshold, and a chi-square probe of missingness against the
  outcome.

Every association is unadjusted. Multivariable and LASSO modelling are out of
scope here and live in a separate Python pipeline.

## Deploying

The container is platform-agnostic: it listens on 7860 by default and honors a
platform-injected `PORT` variable. Every push to `main` re-verifies the image
in CI (build, boot, and a full in-image render to DOCX and PDF).

### Google Cloud Run

Runs the same image with scale-to-zero pricing. From [Cloud
Shell](https://shell.cloud.google.com) in a project with billing enabled:

```bash
git clone https://github.com/rryesuafuga/cohort-profiler
cd cohort-profiler
gcloud run deploy cohort-profiler \
  --source . \
  --region europe-west1 \
  --memory 2Gi --cpu 1 --timeout 3600 \
  --min-instances 0 --max-instances 1 \
  --session-affinity \
  --no-allow-unauthenticated
```

Notes:

- `--no-allow-unauthenticated` keeps the URL closed. Grant the study team
  access by enabling Identity-Aware Proxy on the service and adding their
  Google accounts — do not make a tool that accepts participant records
  public.
- `--session-affinity` matters: Shiny holds a websocket per session.
- `--memory 2Gi` covers a render (R plus LibreOffice); the 512 MB default
  does not.
- The first request after idle pays a cold start (roughly 30-60 s for an
  image this size) on top of the 20-40 s render.
- For continuous deployment, use the service's "Set up continuous
  deployment" button in the console and point it at this repo's `main`.

### Hugging Face Spaces

The frontmatter at the top of this file is the Space's configuration; Spaces
reads it from the README rather than a separate file. Docker Spaces require a
paid plan. Two things to know:

- **Set the Space to private from the start.** Spaces are public by default,
  which is not appropriate for a tool that accepts participant records.
- Free-tier Spaces sleep when idle and their storage is ephemeral. Nothing here
  writes anything it needs to keep: renders happen in `tempdir()`, and uploads
  and outputs are deleted when the session ends.
